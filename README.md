# endpoint-discovery-go

网页端点发现与内容枚举引擎：输入一个目标地址与一组候选路径，引擎并发探测，
给出可复现（确定性）的发现结果。支持范围控制、全局限速、软 404 判定、
断点续扫与凭据脱敏。

## 构建与使用

```sh
go build ./cmd/endscan
./endscan -target http://127.0.0.1:8080/app -words words.txt \
    -rps 20 -concurrency 4 -state scan.state -expand
```

参数：

| 参数 | 默认 | 说明 |
|---|---|---|
| `-target` | （必填） | 目标基地址，如 `http://127.0.0.1:8080/app` |
| `-words` | （必填） | 候选路径词表文件，每行一个，`#` 开头为注释 |
| `-concurrency` | 4 | 单目标最大并发请求数 |
| `-rps` | 20 | 全局请求速率上限（次/秒） |
| `-max-retries` | 3 | 429/5xx/连接失败时的最大重试次数 |
| `-timeout` | 10s | 单请求超时 |
| `-state` | 空 | 断点续扫检查点文件；为空则不持久化 |
| `-expand` | false | 从可用响应中提取链接动态扩展待探测集合 |
| `-max-depth` | 1 | 内容扩展深度 |
| `-prefix` | 目标路径 | 额外允许的路径前缀（可重复） |
| `-exclude` | 无 | 排除的路径前缀（可重复，优先级最高） |
| `-H` | 无 | 自定义请求头 `Name:Value`（可重复，可携带凭据） |

## 范围规则（Scope）

1. 目标地址与所有候选路径先**规范化**再判定：协议与主机名小写、补全默认
   端口、路径解析 `.`/`..` 与重复斜杠、统一大小写、去除结尾斜杠与查询串。
2. 默认范围 = 目标的协议 + 主机 + 端口 + 目标路径所在目录前缀。
3. `-prefix` 按**路径段**匹配：`/app` 允许 `/app/x`，但不允许 `/apple`。
4. `-exclude` 优先于一切允许规则。
5. 范围外或未授权的主机/端口/协议**直接拒绝，不发出任何请求**
   （计入 `stats.rejected`）。重定向跳到范围外时同样停止跟随。

## 判定语义（Classification）

每个路径的判定是确定性的：

| 分级 | 含义 |
|---|---|
| `available` | 2xx 且与不存在路径基线**不逐字节等价**的真实内容 |
| `soft_404` | 2xx 但与"不存在路径"基线响应**完全等价**（状态码相同且正文逐字节一致） |
| `not_found` | 404 / 410 |
| `redirect` | 3xx 重定向（链在 `MaxRedirects` 内未到达最终非重定向响应） |
| `auth_required` | 401，鉴权缺失或失效——**不会**被当作目标不可用 |
| `forbidden` | 403 |
| `error` | 重试耗尽后的 429/5xx 或传输错误 |

### 软 404 的等价语义（严格逐字节）

每次扫描先探测固定的不可能路径 `/.endscan-baseline-3f9a1c7e`（固定值
保证可复现），记录其**最终响应**的状态码、正文长度与正文 SHA-256。

判定一个 2xx 响应是否等价于"提示页"时**只接受严格相等**：

1. 状态码必须与基线一致；并且
2. 正文长度必须相同（长度不同必然正文不同，用作廉价前置过滤）；并且
3. 正文 SHA-256 必须相同，即每个字节都一致。

**仅大小相同不算等价。** 真实站点常有与固定提示页恰好同长度的真实页面；
旧版"同状态且同长度即判 soft_404"会把这类页面错误吞掉。现在正文不同的
响应绝不会因为长度相等被并入不可用。只有正文确实与提示页逐字节一致才判
`soft_404`。

基线探测与普通探测走**同一套手动重定向跟随逻辑**（默认最多 5 跳，每跳都
经过限速、退避与范围检查）。因此当目标对不存在路径返回 3xx 跳转到固定提示
页时，学到的基线就是跳转后的最终页面；一条最终落到提示页（或硬 404 等
不可用页面）的重定向链，其判定与**直接访问该最终页面完全一致**，不会因为
"经过了跳转"就把不可用页面当成真实可用。跟随到最终非重定向响应时，
`redirect_to` 记录最终位置；跳出范围或超过跳数则记为 `redirect`。

## 限速与重试

- **全局限速**：令牌桶，容量 1，速率 `-rps`；第一个请求立即发出，之后
  按 `1/rps` 间隔发放。
- **单目标并发**：信号量，上限 `-concurrency`。
- **重试**：429、5xx 与连接错误按指数退避重试（100ms 起、2s 封顶，
  确定性无抖动）。**每次重试都重新经过限速器与并发信号量**，因此重试
  不会放大流量。

## 归一化与去重规则

候选路径在任何判定、范围检查或去重之前先**规范化**，等价写法归并为同一个
规范标识（canonical key = `scheme://host:port` + 规范路径）：

1. scheme 与 host 转小写，补全默认端口（http→80、https→443）；
2. 路径解析 `.`/`..` 段并折叠重复斜杠，统一**小写**，去掉**结尾斜杠**
   （根路径保留为 `/`）；
3. **丢弃查询串与 fragment**：`/Admin`、`/admin/`、`/ADMIN?x=1`、
   `/admin?y=2` 归并为同一个标识 `http://host/admin`。

去重以规范标识为唯一键，发生在两个层面且都是原子的：

- **入队去重**：状态存储的 `MarkDiscoveredIfNew` 在同一把锁内完成
  "检查 + 落盘 + 更新"，并发扩展或大规模候选（上千条）下也恰好只有一个
  调用者赢得入队，重复写法不会产生第二个任务；
- **在途去重**：worker 取出任务后再用规范键做一次 in-flight 去重。

因此同一路径**只发出一次 HTTP 请求**（每次扫描固定的一次软 404 基线探测
除外），结果中只保留一条记录。测试用回环服务器统计它实际收到的请求，可
直接验证重复请求数为 0。

### 动态扩展

`-expand` 开启后，从 `available` 响应的 `href`/`src` 中提取链接，经同样的
规范化、范围检查与原子去重后加入待探测队列；已在词表中出现的链接不会被
请求第二次。

## 断点续扫

`-state` 指定的检查点文件是**追加式 JSONL 日志**，每行一个事件：
`discover`（已发现/入队）、`finding`（结果已确定并落盘）、`done`（确认
完成）。每条记录写入后都 `fsync`，末尾被崩溃截断的半行在重载时被忽略。

### 完成语义：只有"确认完成"才算完成

一个路径被标记 `done` 必须**先**成功持久化它的 `finding`、**再**写 `done`
事件。扫描被取消（Ctrl-C / SIGTERM / context 取消）时，任何仍在途、尚未
走完"finding + done"两步的路径**都不会**被计为已完成，恢复时一律重新探测。
由此保证：

- 已 `done` 的路径直接跳过（计入 `stats.resumed`），**零重复请求**；
- 只有 `discover`（或只有 `finding` 而无 `done`）的路径在恢复时重新入队，
  **不遗漏**；
- `finding` 先于 `done` 落盘，即使在两者之间崩溃，恢复时也只是重新探测并
  覆盖同键结果，最终发现集合仍然不重复、不遗漏；
- 上一轮由内容扩展发现、但不在当前词表里的未完成键，也会从检查点的 pending
  集合中被重放完成；
- 同一词表用同一检查点重复执行任意次，结果（发现集合、分级、排序）一致；
  全部完成后再次运行不会对任何词表路径发出请求（只有固定基线每次重新学习）。

### 如何验证

- 检查点是纯文本 JSONL，可直接查看事件顺序（`discover → finding → done`）；
- 自动化测试用"门控回环服务器"精确控制哪些响应在取消前完成，断言取消后
  `done` 集合恰好等于已确认路径、停放中的路径恢复后被重新探测、第三轮运行
  是不产生任何额外请求的幂等 no-op；
- 服务器统计每个规范路径实际收到的请求数，已确认路径恢复后命中数必须恰为
  1，用于验证"重复请求为 0、遗漏为 0"。

## 凭据与脱敏

`-H` 可携带 `Authorization`、`X-Api-Key` 等凭据头。敏感头的值**永不**
出现在日志或结果中：`Authorization`、`Cookie`、`Set-Cookie`、
`Proxy-Authorization`、`X-Api-Key` 及 `Config.SensitiveHeaders` 列出的
头在输出时一律替换为 `***`。401 会被识别为 `auth_required` 而非目标
不可用。

## 结果稳定性

同一目标与同一输入下，无论并发度（单目标并发取较小值或较大值）、完成顺序
或中断恢复如何：

- 发现集合一致（按规范化路径去重，候选扩大到上千条仍正确）；
- 分级一致（确定性判定规则 + 固定基线路径 + 严格逐字节等价）；
- 输出排序一致（按 `path` 再按 `class` 排序）。

## 测试

```sh
go test ./...                 # 单元 + 回环服务集成测试
go test -race ./...           # 竞态检测
go test -race -count=5 ./... # 重复 5 次，稳定全绿
```

集成测试用本地回环服务模拟并统计服务器**实际收到的请求**，覆盖：

- 查询串 / 大小写 / 结尾斜杠差异归并为同一标识，重复请求为 0；
- 正文与提示页不同但**大小相同**的真实页面必须判 `available`；
- 重定向链最终落到提示页 / 硬 404 时与直接访问判定一致；
- 不同并发度（1/8/32）下上千候选的集合、分级、排序字节级一致；
- 门控式中断续扫的多次重复执行：只有已确认路径跳过，集合不重不漏、
  重复运行为幂等 no-op；
- 状态存储 `MarkDiscoveredIfNew` 的高并发原子性（同一键恰好一个赢家）。
