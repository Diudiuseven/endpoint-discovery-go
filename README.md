# endpoint-discovery-go

网页端点发现与内容枚举引擎：输入一个目标地址与一组候选路径，引擎并发探测，
给出可复现（确定性）的发现结果。支持范围控制、全局限速、软 404 判定、
断点续扫与凭据脱敏。

## 构建与使用

```sh
go build ./cmd/endscan
./endscan -target http://127.0.0.1:8080/app -words words.txt \
    -rps 20 -concurrency 4 -state scan.state -expand
```

参数：

| 参数 | 默认 | 说明 |
|---|---|---|
| `-target` | （必填） | 目标基地址，如 `http://127.0.0.1:8080/app` |
| `-words` | （必填） | 候选路径词表文件，每行一个，`#` 开头为注释 |
| `-concurrency` | 4 | 单目标最大并发请求数 |
| `-rps` | 20 | 全局请求速率上限（次/秒） |
| `-max-retries` | 3 | 429/5xx/连接失败时的最大重试次数 |
| `-timeout` | 10s | 单请求超时 |
| `-state` | 空 | 断点续扫检查点文件；为空则不持久化 |
| `-expand` | false | 从可用响应中提取链接动态扩展待探测集合 |
| `-max-depth` | 1 | 内容扩展深度 |
| `-prefix` | 目标路径 | 额外允许的路径前缀（可重复） |
| `-exclude` | 无 | 排除的路径前缀（可重复，优先级最高） |
| `-H` | 无 | 自定义请求头 `Name:Value`（可重复，可携带凭据） |

## 范围规则（Scope）

1. 目标地址与所有候选路径先**规范化**再判定：协议与主机名小写、补全默认
   端口、路径解析 `.`/`..` 与重复斜杠、统一大小写、去除结尾斜杠与查询串。
2. 默认范围 = 目标的协议 + 主机 + 端口 + 目标路径所在目录前缀。
3. `-prefix` 按**路径段**匹配：`/app` 允许 `/app/x`，但不允许 `/apple`。
4. `-exclude` 优先于一切允许规则。
5. 范围外或未授权的主机/端口/协议**直接拒绝，不发出任何请求**
   （计入 `stats.rejected`）。重定向跳到范围外时同样停止跟随。

## 判定语义（Classification）

每个路径的判定是确定性的：

| 分级 | 含义 |
|---|---|
| `available` | 2xx 且与不存在路径基线**不等价**的真实内容 |
| `soft_404` | 2xx 且与"不存在路径"基线响应**等价**（同状态码且正文逐字节一致） |
| `not_found` | 404 / 410 |
| `redirect` | 3xx 重定向（链在 `MaxRedirects` 内未到达最终非重定向响应） |
| `auth_required` | 401，鉴权缺失或失效——**不会**被当作目标不可用 |
| `forbidden` | 403 |
| `error` | 重试耗尽后的 429/5xx 或传输错误 |

软 404 基线：每次扫描先探测一个固定的不可能路径
`/.endscan-baseline-3f9a1c7e`（固定值保证可复现），**跟随其重定向链**
（有些站点把不存在路径 302 到提示页），记录最终响应的状态码与正文哈希
作为等价判据。

**等价语义**：只有状态码相同且正文逐字节一致（SHA-256 相等）的响应才判为
`soft_404`。正文不同但长度恰好相同的真实页面**绝不**会被并入不可用，
一律判为 `available`。

重定向链会被手动跟随（默认最多 5 跳，每跳都经过限速与范围检查），并对
**最终响应**做与直接访问完全相同的判定：跳到提示页与直接访问提示页同为
`soft_404`，跳到 404 同为 `not_found`，跳到真实页面同为 `available`——
经过跳转不会把不可用页面当成真实可用。跟随到最终可用响应时
`redirect_to` 记录最终位置。

## 限速与重试

- **全局限速**：令牌桶，容量 1，速率 `-rps`；第一个请求立即发出，之后
  按 `1/rps` 间隔发放。
- **单目标并发**：信号量，上限 `-concurrency`。
- **重试**：429、5xx 与连接错误按指数退避重试（100ms 起、2s 封顶，
  确定性无抖动）。**每次重试都重新经过限速器与并发信号量**，因此重试
  不会放大流量。

## 归一化与去重

- 每个候选路径在**判定之前**先归一化为唯一标识（canonical key）：
  协议与主机名小写、补全默认端口、路径解析 `.`/`..` 与重复斜杠、
  路径统一小写、去除结尾斜杠（根路径除外）、**丢弃查询串与片段**。
- 词表条目里写在路径后的 `?query` / `#frag` 会在拼接 URL 之前剥离，
  不会被转义进路径（否则 `%3F` 会让每个查询串写法变成不同目标）。
- 因此 `/Admin`、`/admin/`、`/ADMIN?x=1`、`/admin?y=2` 是**同一路径**：
  只发出一次请求，结果里只保留一条记录。去重键为
  `scheme://host:port + 规范化路径`。
- `-expand` 开启后，从 `available` 响应的 `href`/`src` 中提取链接，
  经同样的归一化、范围检查与**原子**去重（检查与落盘在同一把锁内完成）
  后加入待探测队列；上千条候选、任意并发度下每个路径也只请求一次。

## 断点续扫

`-state` 指定的检查点文件是**追加式 JSONL 日志**，事件包括
`discover`（入队）、`finding`（结果确定）、`done`（完成）。每条事件
写入后即 `fsync`，崩溃产生的残缺尾行在加载时被忽略。

**完成语义**：一个路径只有在结果已经**持久化**之后才会被标记 `done`；
`finding` 写失败时绝不写 `done`。因此：

- 已 `done` 的路径直接跳过（计入 `stats.resumed`），不会重复请求；
- 已 `discover` 但未 `done` 的路径重新入队重探，不会遗漏；
- 扫描被取消时，进行中的路径**不会**被标记完成；
- 恢复时只预载**已确认完成**（有 `done`）的 finding；只有 `finding`
  没有 `done` 的条目视为未确认，会被重新探测并以新结果为准——
  未确认完成的路径绝不被计为已完成；
- 同一词表重复执行：已完成后的再次运行是空操作（除基线探测外零请求），
  多次中断-恢复的最终发现集合与一次不间断运行**逐字节一致**，不重复
  不遗漏。

**验证方法**：集成测试用记录实际请求数的本地回环服务断言——规范化路径
的重复写法只产生一次请求；多次中断续扫后与参照运行的发现集合完全一致；
已完成运行重复执行时词表路径零新增请求。运行
`go test -race -count=5 ./...` 可复现验证。

## 凭据与脱敏

`-H` 可携带 `Authorization`、`X-Api-Key` 等凭据头。敏感头的值**永不**
出现在日志或结果中：`Authorization`、`Cookie`、`Set-Cookie`、
`Proxy-Authorization`、`X-Api-Key` 及 `Config.SensitiveHeaders` 列出的
头在输出时一律替换为 `***`。401 会被识别为 `auth_required` 而非目标
不可用。

## 结果稳定性

同一目标与同一输入下，无论并发度与完成顺序如何：

- 发现集合一致（按规范化路径去重）；
- 分级一致（确定性判定规则 + 固定基线路径）；
- 输出排序一致（按 `path` 再按 `class` 排序）。

## 测试

```sh
go test ./...                  # 单元 + 回环服务集成测试
go test -race -count=5 ./...   # 竞态检测 + 重复执行稳定性
```

集成测试用**记录实际收到请求**的本地回环服务模拟并断言：

- 归一化去重：大小写 / 结尾斜杠 / 查询串差异的写法只请求一次、只出一条
  发现（重复请求数为零）；
- 软 404：正文与提示页逐字节一致才判等价；正文不同但长度相同的真实页面
  必须判为 `available`；
- 重定向链：落到提示页 / 404 / 真实页面的判定与直接访问一致；基线探测
  同样跟随重定向；
- 断点续扫：确定性中断后多次恢复，最终结果与不间断运行逐字节一致；
  已完成运行重复执行是空操作；未确认的 finding 会被重探；
- 并发确定性：1200 条候选（含重复写法共 3600 条）在并发 1 与 16 下
  发现集合、分级与排序完全一致，每个路径恰好请求一次；
- 429 限流重试不放大流量、范围外目标零请求、凭据头脱敏。
